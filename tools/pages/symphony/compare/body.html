Symphony

Symphony, set beside the tools you know

Symphony is a set of rules, kept in a GitHub repository, that let many workers, people and AI agents alike, share one queue of work without taking the same task, losing stalled work or landing anything unchecked. Those rules are not only for code. Below, the same six powers are set beside the tools people already use in seven kinds of work. For what that looks like in practice, see the use cases.

The six powers

  1. One taker per task

    A task is claimed by being first to create its branch, and GitHub refuses the second, so two workers, human or AI, can never hold the same one.

  2. Stalled work comes back

    A claim with no new work for about a day is released and its branch renamed, so the next worker starts from where the last one stopped.

  3. Overlaps are seen early

    Each claim lists the files it will change, and the board says which open work meets which, and in what order it should land.

  4. Nothing lands unchecked

    Work arrives only as a pull request that passes the repository's required check.

  5. No server, flat price

    The bookkeeping runs in GitHub Actions with no AI call, and the AI work runs on a flat Claude plan, within its five-hour and weekly limits, never an API key.

  6. The record is the work

    The queue, the plan, the work and its history are issues, branches and commits that anyone with access can read.

Why it lives in GitHub, Claude Code and Chrome

Building on tools people already have gives four things a separate app would have to win on its own.

  • Trackable history

    Every claim, plan, change and review is a commit or a comment, kept for as long as the repository is.

  • Shareable

    The project is a repository: invite a person and they have the queue, the instructions and the shared memory, on their own Claude account.

  • Visible

    The board, the control panel and the pull requests show who holds what and what is ready, without asking anyone.

  • Extensible

    A new worker is a short file, a new kind of work is an issue form, and anything GitHub Actions can run can join in.
