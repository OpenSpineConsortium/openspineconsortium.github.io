Claude tokens

The Claude accounts your workers run on, as claude-swap shows them: each slot’s use of its five-hour and seven-day windows with when they reset, the per-model weekly limits such as Fable’s, and which slot the auto mode would take now. A slot is an organization secret, SYMPHONY_CLAUDE_1 to SYMPHONY_CLAUDE_8, set by python3 scripts/tokens.py; main is CLAUDE_CODE_OAUTH_TOKEN. GitHub never gives a secret back, so the page reads only the readings on the repository’s branch pool: what each worker’s run saw in Claude’s answers, what the workflow Pool’s one-word probes saw, and what cswap on your machine sent with python3 scripts/tokens.py usage, the only source of the per-model limits. No reading holds a token. Back to the control panel.

Sign in

One press, as on the control panel: GitHub sends you straight back here signed in, and the page reads the branch as you.

Sign in with GitHub switches on once its sign-in service is running; until then, use a token below.

Use a fine-grained token instead The same token as the control panel’s: Contents read reads the readings, Contents and Pull requests write propose the assignments, Actions write starts the workflow Pool. It stays in this browser and goes to GitHub’s API only. Make one at github.com/settings/personal-access-tokens/new. This is a GitHub token: the page never takes a Claude token.

“Read every slot now” starts the workflow Pool, which asks each slot of SYMPHONY_CLAUDE_ACCOUNTS for one word on Haiku: that spends one word of each slot’s window, so nothing reads them on a schedule.

The slots

A slot is held once a window or a model limit reaches 90 percent, until it resets, or for five hours from its reading when its reset is not known. A worker on auto takes, at the start of each run, the free slot with the most room in five hours and then seven days, and the workers of one run take different free slots; a run already going finishes on its account. The Fable limit and the other per-model ones come only from cswap: run python3 scripts/tokens.py usage on your machine to send them.

Which account each worker runs on

Each worker in Actions runs on main, a slot, or auto, from the file .github/symphony/accounts.json; with no file every worker runs on main. The default branch takes only pull requests, so saving here opens one, which takes effect once it merges. @claude and the coordinator stay on main.
