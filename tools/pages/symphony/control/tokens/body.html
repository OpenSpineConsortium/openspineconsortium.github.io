Claude tokens

The Claude accounts your workers run on: add one with a press, see how much of each is used and when it resets, and choose which worker runs on which. Back to the control panel.

Sign in

One press, as on the control panel: GitHub sends you straight back here signed in, and the page reads the branch as you.

Sign in with GitHub switches on once its sign-in service is running; until then, use a token below.

Use a fine-grained token instead The same token as the control panel’s: Contents read reads the readings, Contents and Pull requests write propose the assignments, Actions write starts the workflow Pool, and the organization permissions Secrets and Variables write add a slot. It stays in this browser and goes to GitHub’s API only. Make one at github.com/settings/personal-access-tokens/new. This is a GitHub token; the one Claude token the page takes is the one you paste under “Add or renew a slot”.

How the readings are taken and how auto picks a slot

A slot is an organization secret, SYMPHONY_CLAUDE_1 to SYMPHONY_CLAUDE_8; main is CLAUDE_CODE_OAUTH_TOKEN. GitHub never gives a secret back, so the page reads only the readings on the repository’s branch pool: what each worker’s run saw in Claude’s answers, what the workflow Pool’s one-word probes saw, and what cswap on your machine sent with python3 scripts/tokens.py usage, the only source of the per-model limits such as Fable’s. No reading holds a token. “Read every slot now” starts the workflow Pool, which asks each slot of SYMPHONY_CLAUDE_ACCOUNTS for one word on Haiku: that spends one word of each slot’s window, so nothing reads them on a schedule.

A slot is held once a window or a model limit reaches 90 percent, until it resets, or for five hours from its reading when its reset is not known. A worker on auto takes, at the start of each run, the free slot with the most room in five hours and then seven days, and the workers of one run take different free slots; a run already going finishes on its account. The Fable limit and the other per-model ones come only from cswap: run python3 scripts/tokens.py usage on your machine to send them.

Add a Claude account

What the button does, and what it needs

It opens an issue on the repository and starts the workflow Token there, which runs claude setup-token on a GitHub Actions runner and posts its sign-in link on the issue. This page shows it as a button: sign in as the account to add, press Authorize, and paste the code claude.ai shows into the box. The run takes the token out of what Claude Code prints and posts it only sealed for GitHub, which alone can open it; the page saves it as the next free slot, as CLAUDE_CODE_OAUTH_TOKEN too while that is not set, lists it in SYMPHONY_CLAUDE_ACCOUNTS so auto and the bench can take it, and closes the issue. The token is never on this page, in the issue or in the log, and lives a year. It needs you to be an owner of the organization, a repository with the workflow Token (symphony-template has it), and the SymphonyBoard App’s permissions Secrets and Variables (organization) and Actions and Issues (repository), each Read and write.

Which account each worker runs on

Where this is kept

Each worker in Actions runs on main, a slot, or auto, from the file .github/symphony/accounts.json; with no file every worker runs on main. The default branch takes only pull requests, so saving here opens one, which takes effect once it merges. @claude and the coordinator stay on main.
