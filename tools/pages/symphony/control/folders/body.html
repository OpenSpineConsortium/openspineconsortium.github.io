Symphony

Folders

A repository that tracks files and folders of your OneDrive, one press per step: connect the drive, tick what to track, make the repository from the template, press Track. From then on the repository’s own workflow, drive-sync.yml, brings what changed in the drive down as a pull request every half hour and sends what changed in the repository back up, and a new comment in a document becomes a task on the board. Google Drive comes later, once there is a way that needs no key. Back to the control panel.

Sign in

One press, as on the control panel: GitHub sends you straight back here signed in, and the page writes the repository as you.

Sign in with GitHub switches on once its sign-in service is running; until then, use a token below.

Use a fine-grained token instead The same token as the control panel’s, with Contents read and write (to write the file that says what is tracked), Secrets read and write (to save the drive’s refresh token as the repository’s secret) and Actions read and write (to start the first sync). It stays in this browser and goes to GitHub’s API only. Make one at github.com/settings/personal-access-tokens/new. This is a GitHub token: the page takes no Claude token, and the drive’s own tokens come from Microsoft when you press Connect.

Refresh asks GitHub for your newest repositories and lists each that was made from the template or carries the topic symphony, so a repository you have just made in step 3 appears here; it also reads the chosen repository again.

What the repository tracks

Step 1: connect the drive

One press: Microsoft asks, on its own page, whether Symphony may read and write your files and keep that access when you are away, and sends you straight back here. The page then holds the drive’s two tokens in its memory alone, never in the browser’s storage, so finish the steps in one sitting: a reload forgets them, and Connect is one press again.

Google Drive comes later, once there is a way that needs no key: Google’s own picker takes a browser API key, which the owner has declined.

Step 2: tick what to track

Your OneDrive, drawn here from Microsoft Graph as you, in this browser: open a folder with Open, tick a file or a folder to track it, and untick to let it go. A ticked folder is tracked with everything in it, six levels down. Nothing of the list leaves this browser but the names and ids of what you tick, which go into the repository’s file.

Ticked:

    Step 3: make the repository

    Skip this step where you already have a repository: pick it above. For a new one, GitHub’s own form makes it from the template, named by you, so its first commit stays yours and no App needs to administer it.

    Make a repository from the template

    The form opens in a new tab. Name the repository, press “Create repository”, then come back here, press Refresh and pick the new repository in the repository field. Signed in with GitHub, the page reaches it once SymphonyBoard is installed on it (an installation on all your repositories covers it); a fine-grained token reaches what it was made for.

    Step 4: track

    One press writes three things, as you: the drive’s refresh token, sealed in this browser with the repository’s public key the way GitHub’s own secrets page seals one, as the secret SYMPHONY_DRIVE_REFRESH; the file .github/symphony/drive.json naming the drive, the folder and what you ticked; and the first run of the sync. The page then drops the drive’s tokens from its memory. A Microsoft refresh token lasts 90 days, and the run cannot keep the newer one Microsoft issues on each sync, so the page says when to press Connect again; Connect again replaces the secret and keeps what you ticked.

    What this page keeps and sends

    In this browser: the GitHub token, as on the control panel, and the names of the repositories you listed. In the open page’s memory alone, until Track or a reload: the drive’s access token and refresh token. Sent: Microsoft’s one-time code to the sign-in service, which adds the client secret it holds, answers with the two tokens and keeps nothing; the refresh token to the same service when the access token runs out during a sitting; requests to Microsoft Graph, as you, for the list you browse; and to GitHub’s API, as you, the sealed secret, the file and the request to run the sync. The repository’s own run then trades the secret for an access token at the same service on every sync. The developer receives nothing from this page. The Apps’ privacy statement covers it: /symphony/apps-privacy.html.
