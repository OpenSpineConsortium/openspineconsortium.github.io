Symphony

Control panel

Your Symphony repositories from one page: the board, the queue, the workers, the checks and the pull requests, and a box to ask Claude. The page talks to GitHub’s API as you, from this browser, and to nothing else; the token stays in this browser. Every state here is written in words and every action is a button or a link with a name, so you and a browsing Claude read and drive it alike. Open /symphony/control/?repo=OWNER/NAME to land on one repository. What it costs, against the other ways of running agents, is on the cost page. The Claude accounts the workers run on, their use and resets and which worker takes which, are on the Tokens page.

Sign in

One press: GitHub asks, the first time only, whether SymphonyBoard may act as you, and sends you straight back here signed in. The token GitHub issues is kept only in this browser, lasts eight hours at a time (the page renews it as you go), and reaches only the repositories SymphonyBoard is installed on, within the App’s permissions and your own access; a small stateless service turns GitHub’s one-time code into that token and keeps nothing. The page never takes a Claude token: the workers run on the one the repository holds as its secret.

Sign in with GitHub switches on once its sign-in service is running; until then, use a token below.

Use a fine-grained token instead Make one at github.com/settings/personal-access-tokens/new: name it, pick the repositories Symphony runs in under Repository access, and under Repository permissions set Actions to Read and write (read lists the runs, write starts a workflow), Checks to Read-only, Contents to Read and write (the read shows the board, the write merges a pull request), Issues to Read and write and Pull requests to Read and write; Metadata comes with them. Press Generate token and paste it here. The token is used for GitHub’s API from this browser only; nothing of this site ever receives it. For an organization’s repositories the organization must allow fine-grained tokens (its Settings, Third-party access, Personal access tokens). This is a GitHub token: the page never takes a Claude token, and the workers run on the one the repository holds as its secret.

Add a repository

A repository Symphony set up carries the topic symphony. Name one to put it on the list; name one without the topic and the page gives you the two presses that set Symphony up on it, through the App’s own install page with that repository selected. A new repository starts at github.com/new; come back with its name.

Board

The file STATE.md on the branch board, as the board workflow last wrote it: the claims, the open pull requests, the overlaps, the queue, the issues given to workers and the blockers.

Tasks

The open issues by the protocol’s labels. An issue labelled todo and held by nobody is free for any session or worker to claim; one a worker’s label names waits for that worker; a claim is a branch claude/N. Give an issue to a worker from its row, or ask Claude about it. Open the Task form on GitHub for the same with GitHub’s own page.

Queue a task

Opens an issue labelled todo in the Task form’s shape. A worker in Actions wakes on the label; any session may claim it.

Ask Claude

Write what you want done or answered. Ask Claude opens an issue that mentions @claude, or comments on the issue or pull request whose number you give, and the repository’s Claude workflow answers there on the repository’s own Claude token, within the turn cap the workflow sets. Queue as a task files the same words as a task for the workers and the sessions instead.

Assistant

Ask the repository’s own Claude about the board: what is claimed, what is blocked, what to take next, where something stands. It answers from GitHub Actions on the repository’s own Claude token and only reads, through an issue of yours labelled assistant that the page opens once per repository (“Assistant: your login”); each question is one comment on that issue and one run of the Claude workflow, and the answer comes back here, since the page reads the issue’s comments every few seconds while it waits. The workflow answers only people with write access to the repository. When the answer names an issue or a board section, the page centres that row in the task tables, filters them, or scrolls to the section, and offers a link that opens the issue on GitHub; it opens nothing by itself and changes nothing in the repository.

Workers

The registry under .github/symphony/workers/: each routine or worker in Actions is one file there, and a person’s sessions need none. Adding one opens the “Add a worker” issue; its workflow checks the answers and opens the pull request that adds the file, which joins the registry when it merges. The same form on GitHub: Add a worker.

Pull requests

The open pull requests with the state of the checks on each head. Merge becomes pressable once a pull request is ready and every check has passed; it asks once more, then merges with a merge commit, which needs Contents set to Read and write on the token, and the merge closes the issue the pull request says it closes.

The latest GitHub Actions runs: the required check, the board, the workers, the coordinator, the metrics. Start one by hand: the workers take the queue now instead of at the next six-hourly run, the board is rewritten, the checks run on the default branch, the metrics branch is written.

What this page keeps and sends

In this browser: the GitHub token, until you press Forget the token. With Keep me signed in ticked, it is kept for every tab of this browser, beside the refresh token GitHub issued with it after Sign in with GitHub, with which the page renews the token after its eight hours. Unticked, the token is kept in this tab’s own storage, which the browser clears when the tab closes and brings back when it reopens or restores the tab, and the refresh token is held by the open page alone, never stored, so the renewals end once that page is gone (closed, reloaded, or replaced by another page such as the cost page) and that sign-in ends with its eight-hour token. Also kept: the names of the repositories you listed, the plan you chose on the cost page, and the number of the assistant issue the page opened in each repository. Sent: requests to GitHub’s API, as you, for what the page shows and does (a question to the assistant goes as a comment on that issue, and the page reads the issue’s comments every few seconds while it waits for the answer), and nothing to anyone else, a token you paste included, which GitHub is asked about before the page keeps it; with Sign in with GitHub, GitHub’s one-time code to the sign-in service, which answers with the token and keeps nothing, the refresh token to the same service when the token is renewed, and a sign-in’s token once more when you press Forget the token, or sign in or paste a token GitHub accepts over it, so that GitHub revokes it. The developer receives nothing from this page. The Apps’ privacy statement, which covers it, is at /symphony/apps-privacy.html.
